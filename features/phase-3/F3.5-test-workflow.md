# F3.5 — 测试工作流闭环

> **Phase**: Phase 3 — MCP 工具生态 + 多项目 (MCP & Multi-Project)
> **Priority**: P2
> **Status**: Not Started
> **Dependencies**: F2.5 (代码知识图谱), F2.6 (错误与日志分析)

## 概述

F2.1 中有"测试生成"作为预设 Agent，但只停留在"生成"阶段。开发者需要的是完整闭环：生成测试 → 运行测试 → 解析结果 → 修复失败 → 再运行。F3.5 测试工作流闭环补全了这个链条，提供 `runTests`（测试运行，支持 all/file/pattern/changed + watch 模式）、`parseTestResult`（结构化解析）、`analyzeFailures`（结合知识图谱分析失败根因）、`fixAndRetry`（Agent 修复→应用变更→重新运行）和 `getCoverage`（覆盖率报告 + 对比）。

此外还包含测试质量分析——检测无效测试（只测 happy path、断言不足、mock 过多）、测试重复度、测试速度（慢测试标记）以及测试与代码的覆盖关联分析（从知识图谱分析哪些源码缺少测试覆盖）。这让 Agent 成为一个能自主完成"测试驱动开发"闭环的 AI 伙伴。

## 验收标准

### 功能验收
- [ ] `runTests(opts)`: 支持 scope（all/file/pattern/changed）和 watch 模式
- [ ] `changed` 模式：只跑 git diff 影响的测试
- [ ] `watch` 模式：文件变化时自动重新运行
- [ ] `parseTestResult(rawOutput)`: 结构化解析测试输出（passed/failed/skipped/duration/failures）
- [ ] `analyzeFailures(failures)`: 结合知识图谱分析失败根因，定位源码
- [ ] `fixAndRetry(failures, agentId)`: Agent 执行修复 → 应用变更 → 重新运行 → 返回结果
- [ ] `getCoverage()`: 行覆盖 / 分支覆盖 / 函数覆盖报告
- [ ] 覆盖率对比：与上次覆盖率报告对比（新增/减少）
- [ ] 测试质量分析：检测无效测试（happy path only / 断言不足 / mock 过多）
- [ ] 测试重复度检测：多个测试覆盖同一代码路径
- [ ] 慢测试标记（>1s），建议拆分或 mock
- [ ] 测试与代码的关联：从知识图谱分析哪些源码缺少测试覆盖

### 非功能验收
- [ ] runTests 输出实时流式推送到 UI（不等待完成才显示）
- [ ] watch 模式下文件变化后重新运行延迟 < 2s
- [ ] 大型测试套件（1000+ 测试）结果解析 < 1s

// 测试工作流管理器
interface TestWorkflowManager {
  runTests(opts: {
    scope: "all" | "file" | "pattern" | "changed";  // changed: 只跑 git diff 影响的测试
    watch?: boolean;    // watch 模式
    file?: string;      // scope=file 时指定文件
    pattern?: string;    // scope=pattern 时指定匹配模式
  }): Promise<TestRunResult>;

  parseTestResult(rawOutput: string): Promise<TestRunResult>;
  analyzeFailures(failures: TestFailure[]): Promise<FailureAnalysis[]>;
  fixAndRetry(failures: TestFailure[], agentId: string): Promise<TestRunResult>;
  getCoverage(): Promise<CoverageReport>;
}

// 测试运行结果
interface TestRunResult {
  id: string;
  timestamp: number;
  passed: number;
  failed: number;
  skipped: number;
  duration: number;
  failures: TestFailure[];
  coverage?: CoverageReport;
  projectId: string;
}

// 测试失败
interface TestFailure {
  testName: string;
  file: string;                     // 测试文件
  error: string;
  stackTrace: string;
  expectedValue: string;
  actualValue: string;
  sourceLocation: { file: string; line: number };  // 定位到源码
}

// 失败分析
interface FailureAnalysis {
  failure: TestFailure;
  rootCause: string;               // 根因分析
  relatedCode: { file: string; line: number; snippet: string }[];
  fixSuggestion: string;           // 修复方案
  confidence: number;              // 置信度 0-1
}

// 覆盖率报告
interface CoverageReport {
  lineCoverage: { total: number; covered: number; percentage: number };
  branchCoverage: { total: number; covered: number; percentage: number };
  functionCoverage: { total: number; covered: number; percentage: number };
  files: {
    path: string;
    lineCoverage: number;
    branchCoverage: number;
    functionCoverage: number;
    uncoveredLines: number[];
  }[];
  diff?: {                         // 与上次对比
    lineCoverageDelta: number;
    branchCoverageDelta: number;
    newCoveredFiles: string[];
    newUncoveredFiles: string[];
  };
}

// 测试质量报告
interface TestQualityReport {
  invalidTests: {
    file: string;
    testName: string;
    issue: "happy_path_only" | "insufficient_assertions" | "excessive_mocks";
    description: string;
  }[];
  duplicates: {
    testNames: string[];
    coveredPath: string;           // 共同覆盖的代码路径
  }[];
  slowTests: {
    file: string;
    testName: string;
    duration: number;             // ms
    suggestion: string;           // 拆分或 mock 建议
  }[];
  untestedCode: {
    file: string;
    symbol: string;
    type: "function" | "class" | "method";
    lines: [number, number];
  }[];
}

### 关键实现逻辑

**测试运行（支持 changed 模式）**：

```typescript
// main/services/testing/TestRunner.ts

async function runTests(opts: {
  scope: "all" | "file" | "pattern" | "changed";
  watch?: boolean;
  file?: string;
  pattern?: string;
}): Promise<TestRunResult> {
  const projectContext = await getProjectContext();
  const testCommand = projectContext.testCommand; // 如 "npm test"

  // 构建 test 命令
  let command = testCommand;
  let args: string[] = [];

  switch (opts.scope) {
    case "all":
      // 使用默认 test 命令
      break;
    case "file":
      args = ["--", opts.file]; // 如 npm test -- --grep "test-file"
      break;
    case "pattern":
      args = ["--", "--grep", opts.pattern];
      break;
    case "changed":
      // 获取 git diff 影响的测试文件
      const changedFiles = await getChangedFiles();
      const changedTestFiles = changedFiles.filter(f => isTestFile(f));
      if (changedTestFiles.length === 0) {
        return { passed: 0, failed: 0, skipped: 0, duration: 0, failures: [] };
      }
      args = ["--", ...changedTestFiles];
      break;
  }

  // 执行命令并实时推送输出
  const result = await execAsync(`${command} ${args.join(" ")}`, {
    cwd: projectContext.rootPath,
    timeout: 300000, // 5 分钟超时
  });

  // 解析输出
  return await parseTestResult(result.stdout);
}

// 获取 git diff 影响的文件
async function getChangedFiles(): Promise<string[]> {
  const { stdout } = await execAsync("git diff --name-only HEAD", { cwd: repoPath });
  return stdout.trim().split("\n").filter(Boolean);
}
```

**失败分析（结合知识图谱）**：

```typescript
async function analyzeFailures(
  failures: TestFailure[]
): Promise<FailureAnalysis[]> {
  const analyses: FailureAnalysis[] = [];

  for (const failure of failures) {
    // 1. 定位源码
    const sourceFile = failure.sourceLocation.file;
    const sourceLine = failure.sourceLocation.line;

    // 2. 通过知识图谱获取相关代码上下文
    const symbols = await knowledgeGraph.searchSymbols("", {
      filePath: sourceFile,
    });

    const callGraph = await knowledgeGraph.getCallGraph(
      getSymbolAtLine(symbols, sourceLine),
      { direction: "both", depth: 2 }
    );

    // 3. 读取相关代码段
    const codeSnippet = await knowledgeGraph.readCodeRange(
      sourceFile,
      Math.max(1, sourceLine - 10),
      sourceLine + 10
    );

    // 4. 调用 LLM 分析根因
    const prompt = `Analyze this test failure:

Test: ${failure.testName}
Error: ${failure.error}
Expected: ${failure.expectedValue}
Actual: ${failure.actualValue}
Source: ${sourceFile}:${sourceLine}

Code context:
${codeSnippet.code}

Call graph:
${JSON.stringify(callGraph, null, 2)}

Provide:
1. Root cause analysis
2. Fix suggestion with confidence level (0-1)`;

    const result = await pi.prompt(prompt);
    const analysis = JSON.parse(result.text);

    analyses.push({
      failure,
      rootCause: analysis.rootCause,
      relatedCode: [{ file: sourceFile, line: sourceLine, snippet: codeSnippet.code }],
      fixSuggestion: analysis.fixSuggestion,
      confidence: analysis.confidence,
    });
  }

  return analyses;
}
```

**修复并重试循环**：

```typescript
async function fixAndRetry(
  failures: TestFailure[],
  agentId: string
): Promise<TestRunResult> {
  // 1. 分析失败
  const analyses = await analyzeFailures(failures);

  // 2. 使用指定 Agent 执行修复
  const agent = await getAgent(agentId);

  for (const analysis of analyses) {
    if (analysis.confidence > 0.7) {
      // 高置信度：Agent 直接修复
      await agent.prompt(`
Fix this test failure:
${analysis.failure.testName}
Root cause: ${analysis.rootCause}
Suggested fix: ${analysis.fixSuggestion}
Source: ${analysis.failure.sourceLocation.file}:${analysis.failure.sourceLocation.line}
`);
      // Agent 使用 edit 工具修复代码（走 Checkpoint + Diff 审查流程）
    }
  }

  // 3. 重新运行测试
  const rerunResult = await runTests({ scope: "all" });

  // 4. 如果仍有失败，可以递归（设置最大重试次数）
  if (rerunResult.failed > 0 && retryCount < MAX_RETRIES) {
    return fixAndRetry(rerunResult.failures, agentId);
  }

  return rerunResult;
}
```

**测试质量分析**：

```typescript
async function analyzeTestQuality(): Promise<TestQualityReport> {
  // 1. 获取所有测试文件
  const testFiles = await getTestFiles();
  const sourceFiles = await getSourceFiles();

  // 2. 通过知识图谱分析测试与源码的覆盖关联
  const untestedCode: TestQualityReport["untestedCode"] = [];
  for (const sourceFile of sourceFiles) {
    const symbols = await knowledgeGraph.getSymbolsInFile(sourceFile);
    for (const symbol of symbols) {
      // 检查是否有测试文件引用了这个符号
      const references = await knowledgeGraph.findReferences(symbol.name, {
        filePath: sourceFile,
      });
      const testReferences = references.filter(ref => isTestFile(ref.filePath));
      if (testReferences.length === 0) {
        untestedCode.push({
          file: sourceFile,
          symbol: symbol.name,
          type: symbol.type,
          lines: [symbol.location.startLine, symbol.location.endLine],
        });
      }
    }
  }

  // 3. 检测无效测试（通过 AST 分析测试内容）
  const invalidTests = await detectInvalidTests(testFiles);

  // 4. 检测慢测试（从测试运行历史）
  const slowTests = await getSlowTestsFromHistory();

  // 5. 检测重复测试（覆盖相同代码路径）
  const duplicates = await detectDuplicateTests(testFiles);

  return { invalidTests, duplicates, slowTests, untestedCode };
}
```

## UI/UX 规范

- **TestRunResultCard**: 顶部显示通过（绿色）/失败（红色）/跳过（灰色）数量徽章 + 耗时，下方列出失败测试
- **FailureAnalysisCard**: 每个失败显示根因分析 + 相关代码片段 + 修复建议 + 置信度条形图
- **CoverageReportCard**: 三条覆盖率条形图（行/分支/函数），可展开查看文件级覆盖率
- **TestRunnerView**: 底部面板，实时显示测试输出流，支持运行/停止/watch 开关
- **TestQualityCard**: 四个分区（无效测试/重复测试/慢测试/未测试代码），每项可点击跳转

## 测试要点

- **单元测试**: TestResultParser 对不同测试框架输出的解析正确性、changed 模式文件过滤、慢测试阈值判断
- **集成测试**: runTests→parseResult→analyzeFailures→fixAndRetry 完整闭环、watch 模式文件监听
- **E2E 测试**: Agent 运行测试→失败→分析→修复→重试通过完整流程
