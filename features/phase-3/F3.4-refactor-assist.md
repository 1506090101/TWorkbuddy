# F3.4 — 重构辅助

> **Phase**: Phase 3 — MCP 工具生态 + 多项目 (MCP & Multi-Project)
> **Priority**: P1
> **Status**: Not Started
> **Dependencies**: F2.5 (代码知识图谱)

## 概述

代码重构是开发中的高频需求，但传统工具辅助重构往往停留在文本搜索替换层面，容易遗漏引用点或引入错误。Agent Buddy 的重构辅助基于已构建的代码知识图谱（tree-sitter AST 解析 + SQLite 图存储），实现真正的 AST 级别安全重构——所有操作基于语法树分析，自动找到所有引用点并同步修改，操作前创建 Checkpoint 支持回滚。

本功能提供两类能力：**检测类**（detectCodeSmells 代码异味检测 / detectDuplicates 重复代码检测 / calculateComplexity 复杂度分析）和**执行类**（renameSymbol 符号重命名 / extractFunction 函数提取 / moveSymbol 符号移动 / inlineFunction 函数内联）。所有执行类操作基于 AST，自动更新所有引用点，操作前创建 Checkpoint，支持回滚。

## 验收标准

### 功能验收
- [ ] `detectCodeSmells(file)`: 检测代码异味（long_function / deep_nesting / duplicate_code / god_class / long_parameter_list / dead_code）
- [ ] `detectDuplicates(project?)`: 检测重复代码块，支持跨文件和跨项目
- [ ] `calculateComplexity(file)`: 计算圈复杂度报告
- [ ] `renameSymbol(file, line, newName)`: 基于 AST 重命名符号，自动更新所有引用点
- [ ] `extractFunction(file, startLine, endLine, name)`: 提取选中的代码段为新函数
- [ ] `moveSymbol(symbol, fromFile, toFile)`: 将符号（函数/类/接口）从一个文件移动到另一个文件
- [ ] `inlineFunction(file, functionName)`: 将函数调用内联为函数体
- [ ] 所有执行类操作基于 AST，自动找到并更新所有引用点
- [ ] 操作前创建 Checkpoint，支持回滚
- [ ] 重构结果通过 Diff 审查流程展示（集成 F1.11）

### 非功能验收
- [ ] renameSymbol 在 100+ 引用点的项目中 < 2s 完成
- [ ] 所有重构操作不引入语法错误（AST 验证后再应用）
- [ ] Checkpoint 创建不阻塞重构操作主流程

interface RefactorTools {

  detectCodeSmells: (file: string) => Promise<CodeSmell[]>;
  detectDuplicates: (project?: string) => Promise<DuplicateBlock[]>;
  calculateComplexity: (file: string) => Promise<ComplexityReport>;

  line: number;

    name: string;
    line: number;
    complexity: number;           // 圈复杂度

### 关键实现逻辑

**基于 AST 的安全重命名**：

```typescript
// main/services/refactor/SymbolRenamer.ts

import { Parser } from "tree-sitter";
import TypeScript from "tree-sitter-typescript";

async function renameSymbol(
  repoPath: string,
  file: string,
  line: number,
  newName: string
): Promise<RenameResult> {
  // 1. 解析文件 AST
  const parser = new Parser();
  parser.setLanguage(TypeScript);
  const sourceCode = await fs.readFile(path.join(repoPath, file), "utf-8");
  const tree = parser.parse(sourceCode);

  // 2. 找到指定行的符号定义
  const nodeAtLine = findNodeAtLine(tree.rootNode, line);
  const symbolNode = findSymbolDefinition(nodeAtLine);
  if (!symbolNode) throw new Error("No symbol found at specified line");

  const oldName = symbolNode.text;
  const symbolType = getSymbolType(symbolNode); // function, class, variable, etc.

  // 3. 通过知识图谱查找所有引用点
  const references = await knowledgeGraph.findReferences(oldName, {
    filePath: file,
    project: currentProjectId,
  });

  // 4. 创建 Checkpoint（保存变更前状态）
  const checkpoint = await changeManager.createCheckpoint(
    `Rename ${oldName} to ${newName}`
  );

  // 5. 收集所有需要修改的文件
  const filesToModify = new Set<string>([file]);
  for (const ref of references) {
    filesToModify.add(ref.filePath);
  }

  // 6. 对每个文件进行 AST 级别重命名
  const changes: { file: string; content: string }[] = [];
  for (const filePath of filesToModify) {
    const modified = await renameInFile(repoPath, filePath, oldName, newName, symbolNode);
    changes.push({ file: filePath, content: modified });
  }

  // 7. 应用变更（通过 write 工具，触发 Diff 审查流程）
  for (const change of changes) {
    await fs.writeFile(path.join(repoPath, change.file), change.content);
  }

  // 8. 更新知识图谱索引
  for (const filePath of filesToModify) {
    await knowledgeGraph.onFileChanged(filePath);
  }

  // 9. 生成变更集
  const changeset = await changeManager.getChangeset(checkpoint.id);

  return {
    symbol: oldName,
    newName,
    filesChanged: Array.from(filesToModify),
    referencesUpdated: references.length,
    changeset,
  };
}

// 在文件中执行 AST 重命名
async function renameInFile(
  repoPath: string,
  filePath: string,
  oldName: string,
  newName: string,
  definitionNode: any
): Promise<string> {
  const parser = new Parser();
  parser.setLanguage(getLanguageForFile(filePath));

  const sourceCode = await fs.readFile(path.join(repoPath, filePath), "utf-8");
  const tree = parser.parse(sourceCode);

  // 遍历 AST，找到所有匹配的标识符节点
  const nodesToRename: { startIndex: number; endIndex: number }[] = [];
  walkTree(tree.rootNode, (node) => {
    if (isMatchingReference(node, oldName, definitionNode)) {
      nodesToRename.push({ startIndex: node.startIndex, endIndex: node.endIndex });
    }
  });

  // 从后往前替换（避免索引偏移）
  let result = sourceCode;
  for (let i = nodesToRename.length - 1; i >= 0; i--) {
    const { startIndex, endIndex } = nodesToRename[i];
    result = result.slice(0, startIndex) + newName + result.slice(endIndex);
  }

  return result;
}
```

**函数提取**：

```typescript
async function extractFunction(
  repoPath: string,
  file: string,
  startLine: number,
  endLine: number,
  name: string
): Promise<void> {
  const parser = new Parser();
  parser.setLanguage(getLanguageForFile(file));

  const sourceCode = await fs.readFile(path.join(repoPath, file), "utf-8");
  const tree = parser.parse(sourceCode);

  // 1. 提取选中范围的代码
  const lines = sourceCode.split("\n");
  const extractedCode = lines.slice(startLine - 1, endLine).join("\n");

  // 2. 分析选中代码的输入（外部变量引用）和输出（赋值的外部变量）
  const extractedTree = parser.parse(extractedCode);
  const { inputs, outputs } = analyzeDependencies(extractedTree.rootNode, sourceCode);

  // 3. 生成新函数定义
  const newFunction = generateFunctionDefinition(name, inputs, outputs, extractedCode);

  // 4. 在原位置替换为函数调用
  const callSite = generateFunctionCall(name, inputs, outputs);

  // 5. 创建 Checkpoint
  await changeManager.createCheckpoint(`Extract function ${name}`);

  // 6. 应用变更：插入新函数定义 + 替换原代码为调用
  const newContent = lines.map((line, index) => {
    if (index === startLine - 1) return newFunction + "\n\n" + callSite;
    if (index > startLine - 1 && index < endLine) return null; // 删除原代码
    return line;
  }).filter(Boolean).join("\n");

  await fs.writeFile(path.join(repoPath, file), newContent);

  // 7. 更新知识图谱
  await knowledgeGraph.onFileChanged(file);
}
```

## UI/UX 规范

- **CodeSmellList**: 每条异味显示类型图标（长函数=函数图标、深嵌套=缩进图标）、文件位置、严重度颜色标签（红/黄/蓝）、建议文字
- **DuplicateList**: 每组重复显示多个实例（文件+行范围），相似度百分比，一键"提取为公共函数"按钮
- **ComplexityReport**: 函数列表，每行显示函数名 + 复杂度条形图 + 严重度颜色
- **RefactorResultCard**: 重构后直接集成到 Diff 审查流程，显示变更文件和引用更新数
