# F1.12 多文件变更追踪

> **Phase**: Phase 1 - 基础底座与代码安全  
> **Priority**: P1  
> **Status**: V2 实现中  
> **Dependencies**: F1.6、F1.11

## V2 需求调整

本 Feature 服务于 Agent 工作台，而非传统聊天附件。一个 `WorkSession` 中的多次 `write` / `edit` 必须汇总为任务级变更集，用户能看到 Agent 改了哪些文件、为何修改、涉及哪些 Checkpoint，以及每个文件的审查状态。

V1 草案曾把 Git 所有权矩阵、自动提交和提交信息生成放在本 Feature 中。V2 将这些 Git 写操作后移：首轮只读 Git 上下文保持在 F1.10，任何 `add`、`commit` 或工作区写入都必须另行经过权限与审查设计。

## 首轮实现

- `SessionChangesetView` 聚合会话内持久化的 `Changeset`，按文件合并路径、增删行、Checkpoint、hunk 决定和最新任务原因。
- 工具写入前创建 Checkpoint，写入后捕获 diff；原因使用最近一条用户任务指令，并限制为 240 字符。
- 右侧“变更审查”显示文件路径、变更类型、原因、`+/-` 统计和状态；点击文件复用 F1.11 的 hunk 明细。
- 支持按文件接受/恢复，以及整批接受/恢复。恢复只能由主进程按项目相对路径还原快照，恢复的 Checkpoint 与变更集一并清理。

## 验收

- [x] 同一任务连续修改两个文件时，显示为一个任务级视图。
- [x] 每个文件显示路径、原因、create/modify/delete、行数和状态。
- [x] 文件级与整批接受会持久化 hunk 决定并写入 `WorkEvent`。
- [x] 文件级与整批恢复会还原真实文件，不允许 renderer 直接写盘。
- [x] 空状态、加载、失败状态和刷新入口可用。
- [ ] Git 所有权区分、rename、复杂多 hunk diff、选择性提交和自动 commit 后续交付。

## 验证

在本地 OpenAI 兼容模拟服务中，Agent 连续写入两个文件；确认任务级视图为 2 个待审查文件，单文件接受后状态独立更新，整批接受后均为已接受，整批恢复后两个文件均被删除且变更集为空。
