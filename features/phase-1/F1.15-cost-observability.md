# F1.15 成本与用量可观测

> **Phase**: Phase 1 - 基础底座与代码安全  
> **Priority**: P0  
> **Status**: V2 首轮已实现  
> **Dependencies**: F1.3、F1.14

## V2 需求调整

成本统计服务于开发任务的可控执行，不应把工作台变成聊天产品的计费页。每一次 Provider 请求都应归属到 `WorkSession`、Agent、模型和项目；用户能在会话中看见 token、已定价成本与月度预算预警，并据此暂停、切换模型或调整目标。

V1 草案中的 SQLite/WAL、在线价格表、模型价格对比、趋势图与优化建议保留为后续能力。本轮不内置会随 Provider 变化的价格，也不伪装成本精度：没有用户显式配置模型价格时仅统计 token，并标为“未定价”。

## 首轮实现

- `UsageTracker` 在 `~/.agentbuddy/usage/` 持久化最近 12 个月的请求记录和月度预算，默认上限 `$20`、预警阈值 `80%`。
- 请求优先读取 Provider 返回的 input/output usage；缺失时使用 F1.14 的上下文估算与输出文本估算，并在记录中标识估算来源。
- 定价按 `providerId:modelId` 由用户显式设置，分别配置每百万输入/输出 token 的美元价格；未配置时 `priced` 为 `false`、成本为零。
- IPC 支持按 session、agent、provider 或日期聚合查询，读取/更新月度预算，设置或清除模型定价。
- Composer 底栏显示当前会话累计 token；有已定价请求时显示累计美元成本，否则明确显示“未定价”。
- 月度已定价支出达到阈值时，主进程写入“已达到月度成本预警” `WorkEvent`，避免只依赖短暂的 renderer 提示。

## 数据模型与边界

`ModelUsageRecord` 包含 Provider/模型、输入输出 tokens、耗时、会话/Agent/项目、成本、定价状态及 input/output 是否估算。`SessionUsage` 用于 Composer 摘要；`UsageReport` 提供时间范围和分组汇总；`MonthlyUsageBudget` 包含美元上限和 0-1 阈值。

用量数据、价格和预算只能在主进程持久化。renderer 只经 preload 获取聚合结果，不能写入任意用量记录；API Key 永不进入记录、统计或工作事件。

## 验收

- [x] 每次成功的 Provider 调用记录模型、会话、Agent、项目、耗时、token、成本和估算标记。
- [x] 优先采用 OpenAI 兼容及 Gemini 的返回 usage；无 usage 时按 F1.14 估算。
- [x] 支持 session / agent / provider / day 分组、时间范围、12 个月保留和会话级摘要。
- [x] 支持显式模型定价、月度预算和一次持久化预警事件。
- [x] Composer 显示 token 与已定价成本或“未定价”。
- [x] 设置页提供按 Provider/模型编辑或清除输入、输出每百万 token 价格的入口。
- [ ] 桌面通知、趋势图、价格对比和优化建议在独立后续 Feature 实现。

## 验证

本地 OpenAI 兼容流式 Provider 返回 `prompt_tokens: 100`、`completion_tokens: 20`，并配置输入 `$1/M`、输出 `$2/M`：会话汇总为 `120` tokens、`$0.00014` 和 1 次已定价请求。将月度上限设为 `$0.0001`、阈值设为 50% 后，时间线出现持久化预警，Composer 显示 `120` 与 `$0.0001`。第二个无 usage 的 Provider 请求记录为 `476` 输入估算、`6` 输出估算、`482` tokens，且保持“未定价”。
