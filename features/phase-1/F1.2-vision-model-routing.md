# F1.2 — 视觉模型独立配置与自动路由

> **Phase**: Phase 1 — 基础底座 + 代码安全
> **Priority**: P1
> **Status**: In Progress
> **Dependencies**: F1.1 (多 Provider 注册表)

## 概述

大多数 LLM Provider 将文本对话模型和视觉模型分开定价和部署（如 OpenAI 的 GPT-4o vs GPT-4o-mini，Anthropic 的 Claude Sonnet vs Claude Haiku）。本功能允许用户为视觉任务独立配置模型，并在运行时根据消息内容自动在 Chat Model 和 Vision Model 之间切换。

当用户上传图片、粘贴截图、或 Agent 工具返回图片时，系统自动检测并切换到 Vision Model 进行推理。当对话回到纯文本模式时，自动切回 Chat Model。这种\"无感切换\"让用户无需手动干预模型选择，同时节省成本（避免用昂贵的视觉模型处理纯文本任务）。

该功能还支持 Per-Agent 级别的模型分配——每个自定义 Agent 可以独立配置自己的 Chat/Vision 模型和推理深度（Thinking Level）。如果用户未配置 Vision Model，系统会根据 `fallbackToChatForImages` 设置决定行为：要么回退到 Chat Model（如果它刚好也支持视觉），要么提示用户配置。

## V2 边界：Composer 附件与会话路由

V2 中，图片由 `ComposerContext.attachments` 进入当前 `WorkSession`；路由器必须基于会话即时模型覆盖、Agent 默认分配和图片能力得出有效模型。文本与代码文件只作为上下文附件，不触发 Vision 路由。工具产生的图片、权限确认和失败恢复属于 F1.6 的 `WorkEvent` 流程。

## 技术设计

### 数据模型

```typescript
// 模型分配配置
interface ModelAssignment {
  // 文本对话模型（必选）
  chat: {
    providerId: string;
    modelId: string;
  };
  // 视觉模型（可选）
  vision?: {
    providerId: string;
    modelId: string;
  };
  // 推理深度
  thinkingLevel: "off" | "low" | "medium" | "high";
  // 行为开关
  autoSwitchOnImage: boolean;        // 是否自动切换
  fallbackToChatForImages: boolean;  // 无 Vision Model 时是否用 Chat Model 处理
  retryOnProviderError: boolean;     // Provider 错误时是否重试
}

// Agent 定义中的模型分配
// AgentDefinition 中包含 modelAssignment: ModelAssignment

// 消息内容类型（用于路由判断）
type ContentBlock =
  | { type: "text"; text: string }
  | { type: "image"; source: { data: string; media_type: string } };

// 路由决策结果
interface RoutingDecision {
  useModel: "chat" | "vision";
  reason: string;
  modelAssignment: {
    providerId: string;
    modelId: string;
  };
}
```

### 关键实现逻辑

#### 图片检测与路由决策

```typescript
// main/agent/model-router.ts

/**
 * 分析消息内容，决定使用 Chat Model 还是 Vision Model
 */
function routeModel(
  messageBlocks: ContentBlock[],
  assignment: ModelAssignment,
  contextHasImages: boolean  // 对话历史中是否已有图片（工具返回等）
): RoutingDecision {
  const hasImages = messageBlocks.some(b => b.type === "image")
    || contextHasImages;

  // 无图片 → Chat Model
  if (!hasImages) {
    return {
      useModel: "chat",
      reason: "纯文本消息",
      modelAssignment: assignment.chat,
    };
  }

  // 有图片但未启用自动切换 → Chat Model
  if (!assignment.autoSwitchOnImage) {
    return {
      useModel: "chat",
      reason: "自动切换已禁用",
      modelAssignment: assignment.chat,
    };
  }

  // 有图片 + 已配置 Vision Model → Vision Model
  if (assignment.vision) {
    return {
      useModel: "vision",
      reason: "消息含图片，切换至 Vision Model",
      modelAssignment: assignment.vision,
    };
  }

  // 有图片 + 未配置 Vision Model + 允许回退 → Chat Model
  if (assignment.fallbackToChatForImages) {
    return {
      useModel: "chat",
      reason: "未配置 Vision Model，回退至 Chat Model",
      modelAssignment: assignment.chat,
    };
  }

  // 有图片 + 未配置 Vision Model + 不允许回退 → 抛出
  throw new Error("消息包含图片但未配置 Vision Model，请在设置中配置或启用回退");
}

/**
 * 检测消息是否包含图片内容块
 */
function hasImageContent(blocks: ContentBlock[]): boolean {
  return blocks.some(b => b.type === "image");
}
```

#### Agent 会话中的模型切换集成

```typescript
// 在调用 pi prompt() 之前，根据消息内容动态决定模型
async function sendMessage(
  agentId: string,
  message: UserMessage,
  contextSnapshot: ContextSnapshot
): Promise<void> {
  const assignment = await getModelAssignment(agentId);

  // 获取对话历史中是否有图片（工具返回的截图等）
  const historyHasImages = contextSnapshot.hasImagesInHistory;

  // 路由决策
  const decision = routeModel(
    message.content,
    assignment,
    historyHasImages
  );

  // 动态设置模型
  if (decision.useModel === "vision" && assignment.vision) {
    await session.setModel(
      assignment.vision.providerId,
      assignment.vision.modelId
    );
  } else {
    await session.setModel(
      assignment.chat.providerId,
      assignment.chat.modelId
    );
  }

  // 设置 thinking level
  await session.setThinkingLevel(assignment.thinkingLevel);

  // 发送消息
  await session.prompt(message);
}
```

#### InputBar 中的 Vision Model 提示

```typescript
// 渲染进程中，上传图片后触发的状态更新
function useUploadedImages() {
  const images = useChatStore(state => state.pendingImages);
  const modelAssignment = useProviderStore(state => state.activeModelAssignment);

  const activeVisionModel = useMemo(() => {
    if (images.length === 0) return null;
    if (!modelAssignment.autoSwitchOnImage) return null;

    if (modelAssignment.vision) {
      return `${modelAssignment.vision.providerId}/${modelAssignment.vision.modelId}`;
    }

    if (modelAssignment.fallbackToChatForImages) {
      return `${modelAssignment.chat.providerId}/${modelAssignment.chat.modelId} (回退)`;
    }

    return "未配置 — 需要设置";
  }, [images, modelAssignment]);

  return { images, activeVisionModel };
}
```

## UI/UX 规范

- **Vision Model 提示**：输入区域下方显示一行小字，格式：`图片将使用 Vision Model: anthropic/claude-sonnet`，灰色半透明
- **未配置提示**：红色警告文字 `未配置 Vision Model，图片将无法被识别 [前往设置]`，点击跳转设置
- **回退模式提示**：灰色文字 `未配置 Vision Model，将使用 Chat Model 处理图片（可能不准确）`
- **自动切换禁用**：关闭 `autoSwitchOnImage` 时不显示 Vision Model 提示

## 开放问题

1. 如果 Vision Model 配置了多个，是否需要支持优先级选择（如 gpt-4o 优先，fallback 到 claude）？
2. 对话历史中包含图片时，是否需要对旧消息重新路由（用 Vision Model 重新理解之前的图片）？
3. "autoSwitchOnImage" 和 "fallbackToChatForImages" 的默认值应该是什么？建议默认开启自动切换、关闭回退（强制用户配置）。

## 备注

- 模型切换是纯路由决策，不涉及 Provider 的重新认证或连接
- Vision Model 的 `getModel()` 调用也通过 F1.1 的 `ProviderManager` 注入环境变量
- 该功能与 F1.5（InputBar）和 F1.8（模型分配面板）紧密结合
- Thinking Level 映射到 Pi SDK 的推理深度参数（影响模型的行为策略，如思考步数）
