# F1.6 — Agent 工具执行与权限确认

> **Phase**: Phase 1 — 基础底座 + 代码安全
> **Priority**: P0
> **Status**: In Progress
> **Dependencies**: F1.3 (Pi SDK 集成)

## 概述

Agent 的核心能力之一是**操作本地环境**——读写文件、执行命令、搜索代码。但这种能力需要安全边界：不能无条件让 AI 执行 `rm -rf /`。本功能实现了 Agent 工具体系的两个关键部分：7 个内置工具的注册和分级权限确认机制。

内置工具基于 Pi SDK 的工具系统注册，涵盖文件操作（read/write/edit）、命令执行（bash）、内容搜索（grep/find/ls）。权限模型分为三级：只读操作（read/ls/grep/find）自动放行无需确认；写操作（write/edit）弹出确认对话框；删除和命令执行弹出确认并附加强警告。确认 UI 显示工具名、参数和预期影响，提供三种操作：允许、拒绝、允许并记住（本次会话不再确认同类操作）。

权限确认通过 Pi SDK 的 `beforeToolCall` 钩子实现——在主进程工具执行前拦截，将确认请求发送到渲染进程展示 UI，等待用户决策后继续或中止执行。权限决策缓存为会话级别（不与磁盘持久化），刷新后重置。

## V2 需求调整：工具即工作流事件

V2 将工具执行视为 `WorkEvent`，而不是隐藏在 Agent 输出后的内部实现。每一次工具开始、进度更新、权限请求、决策、完成或失败都必须关联到 `WorkSession`，在工作流时间线和右侧工具面板可见。用户只通过渲染进程确认，不直接接触 Node.js 工具执行。

### V2 交互与恢复要求

- 工具调用必须使用紧凑过程卡片，展示工具名、参数摘要、风险等级、耗时、结果和失败原因。
- 需要确认的操作必须在时间线和右侧面板同步显示审批状态，支持允许、拒绝和本次会话记住决定。
- 工具失败时必须提供重试、继续、停止或重新规划等恢复路径；重试沿用原权限等级，不得静默放宽权限。
- 文件变更、测试结果和工具输出必须成为可持久化事件，应用重启后可继续审查。
- 插件工具必须复用同一权限和事件链，插件上下文不等同于工具授权。

### 当前实现边界

已实现主进程 `BuiltinToolManager` 与 `PermissionManager`：`read`、`ls`、`grep`、`find` 只读自动放行；`write`、`edit` 需要确认；`bash` 以警告级确认、无 shell 子进程和受限环境执行。所有文件路径受当前 `WorkSession.project.rootPath` 约束，拒绝符号链接与项目外访问，读写和输出均有限额。模型通过统一 `<agent-tool>` 指令协议申请工具，主进程执行后将结果写回 Agent 上下文及 `WorkEvent`。当前尚未接入 Provider 原生 function calling、长任务进度、可操作的重试/继续，以及插件实际执行。

## 技术设计

### 数据模型

```typescript
// 工具定义
interface ToolDefinition {
  name: string;
  description: string;
  parameters: Record<string, ToolParameter>;
  permission: "auto" | "confirm" | "confirm_warn";
}

interface ToolParameter {
  type: "string" | "number" | "boolean" | "array" | "object";
  description: string;
  required?: boolean;
  enum?: string[];
  default?: any;
}

// 权限确认请求
interface PermissionRequest {
  id: string; // 请求唯一 ID
  toolName: string;
  toolLabel: string; // 中文显示名
  params: Record<string, any>;
  permission: PermissionLevel; // 权限级别
  impact: string; // 预期影响描述
  timestamp: number;
  sessionId: string;
}

type PermissionLevel = "auto" | "confirm" | "confirm_warn";

// 权限决策
interface PermissionDecision {
  requestId: string;
  action: "allow" | "deny" | "allow_always";
  category?: string; // 记住的类别，如 "file_write" / "bash_exec"
}

// 会话级权限缓存
interface PermissionCache {
  allowedCategories: Set<string>; // "allow_always" 的类别
}
```

### IPC 通道

| 通道                       | 方向        | 参数                 | 返回值             | 说明                            |
| -------------------------- | ----------- | -------------------- | ------------------ | ------------------------------- |
| `tool:permission-request`  | handle→send | `PermissionRequest`  | —                  | 主进程 → 渲染进程，请求权限确认 |
| `tool:permission-response` | send→handle | `PermissionDecision` | —                  | 渲染进程 → 主进程，返回决策     |
| `tool:register`            | invoke      | `ToolDefinition[]`   | `void`             | 注册自定义/扩展工具（Phase 2+） |
| `tool:list`                | invoke      | 无                   | `ToolDefinition[]` | 获取已注册工具列表              |

#### beforeToolCall 权限检查

```typescript
// main/tools/permission-guard.ts

import { BrowserWindow } from "electron";

interface PermissionGuardConfig {
  window: BrowserWindow;
  decisionTimeout: number; // 默认 30000ms
}

class PermissionGuard {
  private cache: Map<string, Set<string>> = new Map(); // sessionId → allowedCategories
  private pendingRequests: Map<
    string,
    {
      resolve: (decision: PermissionDecision) => void;
      timer: NodeJS.Timeout;
    }
  > = new Map();
  private window: BrowserWindow;

  constructor(config: PermissionGuardConfig) {
    this.window = config.window;
  }

  /**
   * 核心方法：检查工具调用是否需要确认
   * 作为 beforeToolCall 钩子使用
   */
  async checkPermission(
    sessionId: string,
    toolName: string,
    params: Record<string, any>,
  ): Promise<PermissionDecision> {
    const toolDef = this.getToolDefinition(toolName);
    if (!toolDef) {
      return { action: "allow" }; // 未注册工具直接拒绝？或允许？（视策略而定）
    }

    // 自动放行
    if (toolDef.permission === "auto") {
      return { action: "allow" };
    }

    // 检查缓存（allow_always 记忆）
    const sessionCache = this.cache.get(sessionId);
    if (sessionCache?.has(toolDef.name)) {
      return { action: "allow" };
    }

    // 判断是否为危险操作
    const isDangerous = this.isDangerousOperation(toolName, params);
    const permission = isDangerous ? "confirm_warn" : "confirm";

    // 需要用户确认
    return this.requestUserPermission(sessionId, {
      toolName,
      toolLabel: this.getToolLabel(toolName),
      params,
      permission,
      impact: this.describeImpact(toolName, params),
    });
  }

  /**
   * 判断是否为危险操作
   */
  private isDangerousOperation(
    toolName: string,
    params: Record<string, any>,
  ): boolean {
    if (toolName === "bash") {
      const cmd = ((params.command as string) || "").toLowerCase().trim();
      const dangerousPatterns = [
        /^rm\s+(-rf?\s+)?[~/]/i, // rm -rf 根目录/家目录
        /^del\s+\/[sw]/i, // Windows del 系统目录
        /^sudo\s+/, // sudo 提权
        />\s*\/dev\//, // 写入设备文件
        /mkfs\./, // 格式化
        /dd\s+if=/, // 磁盘写入
        /chmod\s+777/, // 过度放开权限
        /git\s+push\s+--force/, // 强制推送
      ];
      return dangerousPatterns.some((p) => p.test(cmd));
    }
    return false;
  }

  /**
   * 生成影响描述
   */
  private describeImpact(
    toolName: string,
    params: Record<string, any>,
  ): string {
    switch (toolName) {
      case "write":
        return `将${params.content ? "覆盖" : "创建"}文件: ${params.file_path}`;
      case "edit":
        return `将修改文件 ${params.file_path} 中的内容`;
      case "bash":
        return `将执行命令: ${params.command}`;
      default:
        return `执行 ${toolName} 操作`;
    }
  }

  /**
   * 发送权限请求到渲染进程
   */
  private async requestUserPermission(
    sessionId: string,
    context: Omit<PermissionRequest, "id" | "timestamp" | "sessionId">,
  ): Promise<PermissionDecision> {
    const requestId = `perm_${Date.now()}_${Math.random().toString(36).slice(2, 7)}`;

    const request: PermissionRequest = {
      id: requestId,
      ...context,
      timestamp: Date.now(),
      sessionId,
    };

    return new Promise((resolve) => {
      // 超时自动拒绝
      const timer = setTimeout(() => {
        this.pendingRequests.delete(requestId);
        resolve({ requestId, action: "deny" });
      }, 30000);

      this.pendingRequests.set(requestId, { resolve, timer });

      // 发送到渲染进程
      this.window.webContents.send("tool:permission-request", request);
    });
  }

  /**
   * 接收渲染进程的决策
   */
  handleDecision(decision: PermissionDecision): void {
    const pending = this.pendingRequests.get(decision.requestId);
    if (!pending) return;

    clearTimeout(pending.timer);
    this.pendingRequests.delete(decision.requestId);

    // 处理 allow_always
    if (decision.action === "allow_always" && decision.category) {
      const sessionCache = this.cache.get(decision.category) || new Set();
      sessionCache.add(decision.category);
      this.cache.set(decision.category, sessionCache);
    }

    pending.resolve(decision);
  }

  /**
   * 清除会话缓存
   */
  clearSessionCache(sessionId: string): void {
    this.cache.delete(sessionId);
  }

  /**
   * 清理所有
   */
  dispose(): void {
    for (const [, pending] of this.pendingRequests) {
      clearTimeout(pending.timer);
      pending.resolve({ requestId: "", action: "deny" });
    }
    this.pendingRequests.clear();
    this.cache.clear();
  }
}
```

## UI/UX 规范

- **确认对话框**：居中模态弹窗，宽度 500px，背景半透明遮罩，点击遮罩不关闭（强制决策）
- **危险警告**：红色顶部栏 + 红色边框 + 警告图标，视觉上与普通确认区分
- **参数展示**：`pre` 标签使用等宽字体 + 灰色背景，内容过长时滚动
- **操作按钮**：允许 = 蓝色实心主按钮，拒绝 = 灰色次要按钮，允许并记住 = 蓝色实心 + 书签图标
- **超时提示**：30 秒无操作时自动拒绝并显示 Toast"操作超时已自动拒绝"
- **快捷键提示**：底部灰色文字展示 Enter/Esc 快捷键

## 测试要点

- **单元测试**: 危险命令检测正则（rm -rf /, sudo, dd 等）；权限级别映射；缓存读写
- **集成测试**: beforeToolCall → 权限请求 → 用户决策 → 继续/中止执行；allow_always 缓存生效
- **E2E 测试**: Agent 调用 write → 弹出对话框 → 点击允许 → 文件被写入；Agent 调用 bash rm → 弹出红色警告

## 开放问题

1. "允许并记住" 的类别粒度：是记住工具名（如所有 `write` 操作都放行），还是记住工具名 + 路径模式？
2. 白名单路径是否需要支持（如允许 `write` 但在某个目录范围内自动放行）？
3. 对于 `bash` 命令，是否需要支持命令结果预览（如 `ls` 的输出）？
4. 权限确认超时 30 秒是否合理？是否需要可配置？
