# F1.13 Inline 代码变更应用

> **Phase**: Phase 1 - 基础底座与代码安全  
> **Priority**: P1  
> **Status**: V2 实现中  
> **Dependencies**: F1.11、F1.12

## V2 需求调整

内联 diff 属于 Agent 工作流时间线，不是聊天气泡的附属装饰。Agent 写入或编辑文件后，对应的 `file_change` 事件必须在时间线上渲染可审查卡片；用户不离开当前工作过程就能看路径、原因、差异和审查决定。

V1 草案中的独立 `changeset:*` 通道、全局热键库和 Git 所有权标注不再作为首轮前提。V2 复用 F1.11/F1.12 的 `change:*` 主进程边界；快捷键只在内联卡片获得焦点时生效，绝不覆盖 Composer 的文本编辑行为。

## 首轮实现

- `file_change` 的 `write` / `edit` 事件凭 `changesetId` 渲染 `InlineChangeCard`，展示路径、任务原因、`+/-`、文件展开和 hunk diff。
- 卡片可按 hunk、按 Changeset 接受或恢复；所有操作经 preload 调用主进程，并同步 `WorkEvent`、右侧面板与持久化 hunk 决定。
- 会话完成事件在存在至少两个待审查文件时渲染任务级摘要卡，提供逐文件和整批接受/恢复，并跳转右侧面板查看完整 diff。
- hunk 审查 API 以 `changesetId + path + hunkIndex` 精确定位，避免多文件 Changeset 中相同 hunk 索引误操作。
- 焦点位于卡片时：`Ctrl+Enter` 接受范围内变更，`Ctrl+Backspace` 恢复，`Ctrl+Z` 回滚最后一个 Checkpoint。

## 验证

本地 OpenAI 兼容模拟 Agent 连续写入两个文件。桌面端验证了两张内联卡片与一张任务摘要卡渲染、单卡接受后右侧面板同步、整批接受后 2/2 完成，以及 `Ctrl+Z` 回滚最后一个 Checkpoint。
