# F1.14 上下文预算管理

> **Phase**: Phase 1 - 基础底座与代码安全  
> **Priority**: P0  
> **Status**: V2 实现中  
> **Dependencies**: F1.3、F1.9、F1.10

## V2 需求调整

预算管理服务于每一次 Agent 调用的上下文边界。它必须在主进程将系统提示、项目摘要、Git 摘要、工具协议和会话历史装配为 Provider 请求之前完成计量与裁剪；renderer 只能读取摘要并请求压缩，不能修改运行时历史。

V1 草案假定 Pi SDK、tiktoken、RAG、记忆和 MCP 已可用。V2 首轮不引入未配置的模型或外部 tokenizer：使用可预测的本地中英文混合估算，并只计量当前已存在的五类来源。RAG、记忆与插件上下文会在对应 Feature 交付时作为独立预算来源接入。

## 首轮实现

- `ContextBudgetManager` 在 `~/.agentbuddy/context/` 持久化配置，默认 128k 总预算、4,096 回复预留和五类分配比例。
- Agent 每轮请求按来源裁剪静态上下文，并从末尾选择未超配额的历史消息；`ContextUsage` 缓存在运行时并经 IPC 暴露。
- 当长历史超过配额且存在 6 条以上消息时，自动生成受限长度的早期历史摘要、保留最近预算内消息，并写入可审查工作事件。
- 右侧“上下文预算”面板显示堆叠分布、总量、剩余空间、建议和压缩操作；手动压缩同样由主进程完成。

## 验收

- [x] 配置包含总预算、回复预留、阈值与来源分配，主进程校验分配总和。
- [x] Provider 请求使用预算后的系统提示和历史，而非完整未裁剪历史。
- [x] `ContextUsage` 返回来源明细、可用空间、使用率、历史数量与压缩建议。
- [x] 自动和手动压缩均保留近期上下文并记录 `WorkEvent`。
- [x] 工作台右侧可查看实时分布并触发压缩。
- [ ] 模型专用 tokenizer、RAG/记忆/MCP 按需预算、设置页编辑和跨重启 usage 快照后续实现。

## 验证

桌面端以 1,024 token 临时预算连续发送四条长任务，自动压缩事件出现；以 8,192 token 配置验证手动压缩使历史估算从 7,273 降至 5,498。恢复默认配置后，面板显示系统、项目、工具与历史的实时分布。
