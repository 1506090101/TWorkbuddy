# F6.1 — 定时工作流引擎

> **Phase**: Phase 6 — 定时工作流 + 消息网关 (Workflow & Gateway)
> **Priority**: P0
> **Status**: Not Started
> **Dependencies**: F2.1 (Agent 定义模型与管理)

## 概述

定时工作流引擎让 Agent Buddy 从"被动响应"进化为"主动工作"。用户可以定义定时任务（Cron 调度）、Webhook 触发任务和事件驱动任务，让 Agent 在特定时间或条件下自动执行工作。典型场景包括：每日代码审查报告（Cron `0 18 * * *`）、PR 合并后自动跑测试（Webhook）、文件变化时更新文档（Event）、每周项目摘要（Cron `0 9 * * 1`）。

工作流引擎基于 `node-cron` 在主进程中运行调度器，支持标准 cron 表达式和自然语言配置（通过 LLM 将自然语言转为 cron 表达式）。工作流执行时创建新的 Agent Session（或在已有会话中继续），执行完成后结果输出到配置的渠道（桌面通知/钉钉/微信/QQ/飞书/文件/无输出）。内置 Webhook HTTP 服务器（默认端口 18999）支持外部系统触发。

## 技术设计

### 数据模型

```typescript
// 工作流定义
interface Workflow {
  id: string;
  name: string;
  description: string;

  // 触发方式
  trigger: {
    type: "cron" | "webhook" | "event";
    // cron 模式
    schedule?: string;         // cron 表达式，如 "0 9 * * *" (每天9点)
    naturalLanguage?: string;  // 自然语言描述，如 "每天早上9点"
    // webhook 模式
    webhookPath?: string;      // 如 "/workflow/daily-report"
    webhookToken?: string;     // 验证 Token
    // event 模式
    eventCondition?: string;   // 如 "on:file-change:path=/src/**/*.ts"
  };

  // 执行配置
  agentId: string;             // 使用哪个 Agent
  prompt: string;              // 任务指令
  workspaceId?: string;        // 工作区（项目）

  // 输出配置
  output: {
    channels: OutputChannel[]; // 输出到哪里
    format: "text" | "markdown" | "json";
  };

  // 状态
  enabled: boolean;
  lastRunAt?: number;
  nextRunAt?: number;
}

// 输出渠道
interface OutputChannel {
  type: "desktop-notification" | "dingtalk" | "wechat" | "qq" | "feishu" | "file" | "none";
  target?: string;  // 平台目标（如群 ID、文件路径）
}

// 工作流执行记录
interface WorkflowRun {
  id: string;
  workflowId: string;
  startedAt: number;
  completedAt?: number;
  status: "running" | "completed" | "failed";
  result?: string;              // 结果摘要
  sessionId?: string;           // 关联的会话 ID
  triggerType: "cron" | "webhook" | "event" | "manual";
  logs: WorkflowLogEntry[];     // 执行日志
}

// 执行日志条目
interface WorkflowLogEntry {
  timestamp: number;
  level: "info" | "warn" | "error";
  message: string;
  detail?: string;
}
```

### 关键实现逻辑

**Cron 调度器**：

```typescript
// main/services/workflow/WorkflowEngine.ts

import cron from "node-cron";

class WorkflowEngine {
  private scheduler: Map<string, cron.ScheduledTask> = new Map();
  private webhookServer: http.Server | null = null;

  // 应用启动时恢复所有已启用的工作流
  async initialize(): Promise<void> {
    const workflows = await this.db.getAllWorkflows();
    for (const workflow of workflows.filter(w => w.enabled)) {
      await this.scheduleWorkflow(workflow);
    }
    await this.startWebhookServer();
  }

  // 调度工作流
  async scheduleWorkflow(workflow: Workflow): Promise<void> {
    // 取消已有调度
    if (this.scheduler.has(workflow.id)) {
      this.scheduler.get(workflow.id)!.stop();
    }

    switch (workflow.trigger.type) {
      case "cron":
        if (!workflow.trigger.schedule) return;
        if (!cron.validate(workflow.trigger.schedule)) {
          throw new Error(`Invalid cron expression: ${workflow.trigger.schedule}`);
        }
        const task = cron.schedule(workflow.trigger.schedule, () => {
          this.executeWorkflow(workflow, "cron");
        });
        this.scheduler.set(workflow.id, task);
        task.start();
        break;

      case "webhook":
        // Webhook 触发不需要调度，由 HTTP 服务器处理
        break;

      case "event":
        // 事件触发注册到事件监听器
        this.eventEmitter.on("workflow-event", (event) => {
          if (this.matchEventCondition(event, workflow.trigger.eventCondition!)) {
            this.executeWorkflow(workflow, "event");
          }
        });
        break;
    }

    // 计算下次运行时间
    await this.updateNextRunAt(workflow);
  }

  // 执行工作流
  async executeWorkflow(workflow: Workflow, triggerType: string): Promise<WorkflowRun> {
    const run: WorkflowRun = {
      id: generateId(),
      workflowId: workflow.id,
      startedAt: Date.now(),
      status: "running",
      triggerType,
      logs: [],
    };

    await this.db.saveRun(run);
    this.emit("workflow:event", run); // 推送到 UI

    try {
      this.log(run, "info", `Starting workflow: ${workflow.name}`);

      // 1. 创建新的 Agent Session
      const session = await agentManager.createSession({
        agentId: workflow.agentId,
        workspaceId: workflow.workspaceId,
        title: `[Workflow] ${workflow.name}`,
      });
      run.sessionId = session.id;

      // 2. 执行 prompt
      this.log(run, "info", `Executing prompt: ${workflow.prompt}`);
      const result = await agentManager.prompt(session.id, workflow.prompt);

      // 3. 格式化输出
      const formatted = this.formatOutput(result.text, workflow.output.format);
      run.result = formatted;

      // 4. 发送到输出渠道
      for (const channel of workflow.output.channels) {
        await this.sendToChannel(channel, workflow.name, formatted);
        this.log(run, "info", `Sent to ${channel.type}`);
      }

      run.status = "completed";
      run.completedAt = Date.now();
      this.log(run, "info", "Workflow completed successfully");

    } catch (error) {
      run.status = "failed";
      run.completedAt = Date.now();
      this.log(run, "error", `Workflow failed: ${error.message}`);
    }

    await this.db.updateRun(run);
    await this.db.updateWorkflow(workflow.id, { lastRunAt: Date.now() });
    this.emit("workflow:event", run);

    return run;
  }

  // 自然语言转 cron
  async naturalLanguageToCron(text: string): Promise<{ cron: string; explanation: string }> {
    const prompt = `Convert this natural language time description to a cron expression.

Description: "${text}"

Respond in JSON: { "cron": "...", "explanation": "..." }

Examples:
- "每天早上9点" → { "cron": "0 9 * * *", "explanation": "Every day at 9:00 AM" }
- "每周一上午10点" → { "cron": "0 10 * * 1", "explanation": "Every Monday at 10:00 AM" }
- "每小时第30分钟" → { "cron": "30 * * * *", "explanation": "At minute 30 of every hour" }`;

    const result = await pi.prompt(prompt, { model: getCheapestModel() });
    return JSON.parse(result.text);
  }

  // Webhook HTTP 服务器
  private async startWebhookServer(): Promise<void> {
    const port = 18999; // 默认端口，可配置
    this.webhookServer = http.createServer(async (req, res) => {
      const url = new URL(req.url!, `http://localhost:${port}`);
      const webhookPath = url.pathname;

      // 查找匹配 webhook 路径的工作流
      const workflow = await this.db.getWorkflowByWebhookPath(webhookPath);
      if (!workflow || !workflow.enabled) {
        res.writeHead(404);
        res.end("Workflow not found");
        return;
      }

      // Token 验证
      if (workflow.trigger.webhookToken) {
        const token = url.searchParams.get("token") || req.headers["x-webhook-token"];
        if (token !== workflow.trigger.webhookToken) {
          res.writeHead(401);
          res.end("Unauthorized");
          return;
        }
      }

      // 异步执行工作流
      res.writeHead(200);
      res.end(JSON.stringify({ status: "triggered", workflowId: workflow.id }));
      this.executeWorkflow(workflow, "webhook");
    });

    this.webhookServer.listen(port);
  }
}
```

**输出渠道发送**：

```typescript
async function sendToChannel(channel: OutputChannel, title: string, content: string): Promise<void> {
  switch (channel.type) {
    case "desktop-notification":
      new Notification({ title, body: content.slice(0, 200) }).show();
      break;

    case "file":
      const filePath = channel.target || path.join(os.homedir(), ".agentbuddy/output/workflow-output.md");
      await fs.appendFile(filePath, `\n## ${new Date().toISOString()}\n${content}\n`);
      break;

    case "dingtalk":
    case "wechat":
    case "qq":
    case "feishu":
      // 通过消息网关 (F6.2) 发送
      await messageGateway.sendToChannel(channel.type, channel.target, title, content);
      break;

    case "none":
      // 不输出
      break;
  }
}
```

## UI/UX 规范

- **工作流列表**：每行显示名称 + 触发方式图标 + 下次运行时间 + 状态开关
- **触发配置**：选择触发类型后显示对应配置项——cron 模式有表达式输入框和自然语言输入框（支持互转）
- **执行历史**：时间线形式，每条记录显示时间 + 耗时 + 状态图标 + 结果摘要，点击展开查看完整日志
- **LogViewer**：终端风格，彩色日志级别（info=蓝 / warn=黄 / error=红）

## 测试要点

- **单元测试**: cron 表达式验证、自然语言转 cron、事件条件匹配、输出渠道发送
- **集成测试**: 创建工作流→调度→触发执行→记录历史→查看日志完整流程、Webhook 触发
- **E2E 测试**: 创建每日代码审查工作流，等待触发或手动触发，验证结果输出到指定渠道

## 备注

- 工作流数据存储在 `~/.agentbuddy/data/workflows.db`（SQLite）
- Webhook 服务器默认端口 18999，可在设置中配置
- 输出到消息平台渠道（钉钉/微信/QQ/飞书）依赖 F6.2 消息平台网关
