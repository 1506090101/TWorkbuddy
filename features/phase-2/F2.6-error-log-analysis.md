# F2.6 — 错误与日志分析

> **Phase**: Phase 2 — Agent 编排 + 代码理解
> **Priority**: P1
> **Status**: Not Started
> **Dependencies**: F2.5 (代码知识图谱)

## 概述

错误与日志分析功能让 Agent 能够解析各种错误输出（堆栈跟踪、构建错误、测试失败、运行时日志），自动定位问题根因，关联到具体代码文件和行号，并提出修复建议。用户只需粘贴错误日志或构建输出，Agent 自动检测错误类型、结构化解析、定位源码、分析根因、提出修复方案，用户确认后走 Checkpoint + Diff 审查流程执行修复。

此功能依赖 F2.5 代码知识图谱来快速定位源码——通过 search_symbols 和 find_references 工具，Agent 不需要读取整个文件就能定位错误涉及的符号和代码段，大幅减少 token 消耗。结合知识图谱的关系查询能力，Agent 还能分析错误的影响范围和上下游关联。

## 验收标准

### 功能验收
- [ ] `parseStackTrace` 工具：结构化解析堆栈跟踪，提取帧列表、根因、相关代码
- [ ] `analyzeBuildError` 工具：解析构建错误输出，提取错误列表、受影响文件、修复建议
- [ ] `analyzeTestFailure` 工具：解析测试失败输出，定位失败的测试用例和源码位置
- [ ] `parseLogs` 工具：日志解析，按 level（error/warning/info）和 pattern 过滤
- [ ] `findErrorPatterns` 工具：错误模式匹配，发现重复出现的错误模式
- [ ] `locateSource` 工具：根据堆栈帧定位到具体文件和行号，提取上下文片段
- [ ] 自动检测错误类型（堆栈跟踪 / 构建错误 / 测试失败 / 运行时日志）
- [ ] 根因分析：LLM 结合知识图谱上下文分析错误原因
- [ ] 修复建议：提出具体修改方案
- [ ] 用户确认后走 Checkpoint + Diff 审查流程执行修复
- [ ] 错误位置可点击跳转到代码编辑器
- [ ] 支持多种语言/框架的错误格式（JS/TS/Python/Rust/Go/Java）

### 非功能验收
- [ ] 堆栈跟踪解析 < 500ms（不含 LLM 分析）
- [ ] 源码定位 < 200ms（通过知识图谱查询）
- [ ] 根因分析 LLM 调用 < 10 秒
- [ ] 大日志（10000+ 行）解析不卡顿

```typescript
// shared/types/debug.ts

/** 堆栈帧 */
interface StackFrame {
  filePath: string;
  line: number;
  column?: number;
  functionName: string;
  isNative: boolean;            // 是否原生代码帧
  isProject: boolean;           // 是否项目代码（非 node_modules）
  source?: string;              // 该行源码片段
}

/** 解析后的堆栈跟踪 */
interface ParsedStackTrace {
  errorType: string;            // 如 "TypeError", "ReferenceError"
  errorMessage: string;
  frames: StackFrame[];
  rootCause: string;            // LLM 分析的根因
  relatedCode: {                // 相关代码片段
    file: string;
    line: number;
    snippet: string;
  }[];
  suggestion: string;           // 修复建议
}

/** 构建错误 */
interface BuildError {
  file: string;
  line: number;
  column?: number;
  severity: "error" | "warning";
  code: string;                // 错误码，如 "TS2304"
  message: string;
  context?: string;            // 错误上下文代码
}

/** 构建错误分析 */
interface BuildErrorAnalysis {
  errors: BuildError[];
  summary: string;             // 错误摘要
  affectedFiles: string[];
  fixSuggestions: FixSuggestion[];
}

/** 修复建议 */
interface FixSuggestion {
  file: string;
  line: number;
  description: string;          // 问题描述
  suggestion: string;          // 具体修复方案
  confidence: "high" | "medium" | "low";
}

/** 日志条目 */
interface LogEntry {
  timestamp?: string;
  level: "error" | "warning" | "info" | "debug" | "trace";
  message: string;
  source?: string;             // 来源组件
  raw: string;                 // 原始行
}

/** 错误模式 */
interface ErrorPattern {
  pattern: string;             // 匹配模式
  occurrences: number;
  firstSeen: string;
  lastSeen: string;
  severity: "error" | "warning" | "info";
  sampleLog: string;
}

/** 测试失败分析 */
interface TestFailureAnalysis {
  failures: TestFailureDetail[];
  summary: string;
  rootCauses: string[];
  fixSuggestions: FixSuggestion[];
}

interface TestFailureDetail {
  testName: string;
  suite: string;               // 测试套件
  file: string;
  error: string;
  stackTrace: string;
  expectedValue: string;
  actualValue: string;
  sourceLocation: { file: string; line: number };
}

/** 定位源码结果 */
interface SourceLocation {
  file: string;
  line: number;
  snippet: string;            // 该行附近代码片段
  symbolName?: string;         // 所属符号名
  symbolSummary?: string;      // 符号摘要（来自知识图谱）
}
```

**堆栈跟踪解析**:

```typescript
// main/services/debug-tools/stack-trace-parser.ts

/** 解析原始堆栈跟踪文本 */
export function parseStackTraceRaw(raw: string): Omit<ParsedStackTrace, "rootCause" | "relatedCode" | "suggestion"> {
  const lines = raw.split("\n").map(l => l.trim());
  
  // 提取错误类型和消息（第一行）
  const firstLine = lines[0];
  const errorMatch = firstLine.match(/^(\w*(?:Error|Exception)):\s*(.*)$/);
  const errorType = errorMatch?.[1] || "Error";
  const errorMessage = errorMatch?.[2] || firstLine;

  // 解析堆栈帧
  const frames: StackFrame[] = [];
  const frameRegex = [
    // V8/Node.js 格式: "at functionName (filePath:line:column)"
    /^\s*at\s+(.+?)\s+\((.+?):(\d+):(\d+)\)$/,
    // "at filePath:line:column"
    /^\s*at\s+(.+?):(\d+):(\d+)$/,
    // Python 格式: 'File "path", line N, in func'
    /^\s*File\s+"(.+?)",\s+line\s+(\d+),\s+in\s+(.+)$/,
    // Java 格式: "at package.Class.method(File.java:line)"
    /^\s*at\s+([\w.]+)\(([\w.]+):(\d+)\)$/,
  ];

  for (const line of lines.slice(1)) {
    for (const regex of frameRegex) {
      const match = line.match(regex);
      if (match) {
        // 根据匹配格式提取字段
        if (regex === frameRegex[0]) {
          // V8 格式
          const filePath = match[2];
          frames.push({
            functionName: match[1],
            filePath,
            line: parseInt(match[3]),
            column: parseInt(match[4]),
            isNative: false,
            isProject: !filePath.includes("node_modules"),
          });
        } else if (regex === frameRegex[2]) {
          // Python 格式
          frames.push({
            functionName: match[3],
            filePath: match[1],
            line: parseInt(match[2]),
            isNative: false,
            isProject: true,
          });
        }
        break;
      }
    }
  }

  return { errorType, errorMessage, frames };
}
```

**通过知识图谱定位源码**:

```typescript
// main/services/debug-tools/source-locator.ts

/** 通过知识图谱定位源码，避免读取整个文件 */
async function locateSourceViaGraph(
  graph: KnowledgeGraph,
  filePath: string,
  line: number
): Promise<SourceLocation> {
  // 1. 获取文件摘要
  const fileSummary = await graph.getFileSummary(filePath);
  
  // 2. 查找该行所在的符号
  const symbols = await graph.getSymbolsByFile(filePath);
  const containingSymbol = symbols.find(s =>
    line >= s.location.startLine && line <= s.location.endLine
  );
  
  // 3. 读取该行附近的代码段（通过 read_code_range）
  const startLine = Math.max(1, line - 5);
  const endLine = line + 5;
  const codeResult = await graph.readCodeRange(filePath, startLine, endLine);
  
  return {
    file: filePath,
    line,
    snippet: codeResult.code,
    symbolName: containingSymbol?.name,
    symbolSummary: containingSymbol?.summary,
  };
}
```

```typescript
// main/services/debug-tools/root-cause-analyzer.ts

async function analyzeRootCause(
  llmClient: LLMClient,
  parsed: ParsedStackTrace
): Promise<{ rootCause: string; relatedCode: any[]; suggestion: string }> {
  const projectFrames = parsed.frames.filter(f => f.isProject);
  
  const prompt = `分析以下错误的根本原因并提出修复建议。

错误类型: ${parsed.errorType}
错误消息: ${parsed.errorMessage}

堆栈跟踪（项目代码部分）:
${projectFrames.map(f => 
  `  ${f.functionName} (${f.filePath}:${f.line})\n  源码: ${f.source || "N/A"}`
).join("\n")}

请分析：
1. 根本原因是什么？
2. 哪些代码与此错误相关？
3. 具体的修复建议是什么？

请用 JSON 格式返回：
{
  "rootCause": "...",
  "relatedCode": [{ "file": "...", "line": 1, "snippet": "..." }],
  "suggestion": "..."
}`;

  const result = await llmClient.complete({
    messages: [{ role: "user", content: prompt }],
    maxTokens: 1000,
  });
  
  try {
    return JSON.parse(result.content);
  } catch {
    return {
      rootCause: result.content,
      relatedCode: [],
      suggestion: "请查看分析结果",
    };
  }
}
```
