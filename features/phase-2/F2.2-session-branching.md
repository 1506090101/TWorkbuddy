# F2.2 会话分支系统

> **Phase**: Phase 2 - Agent 编排与代码理解  
> **Priority**: P0  
> **Status**: V2 首轮已实现  
> **Dependencies**: F1.3、F2.1、F2.4

## V2 需求调整

分支用于让用户把当前开发任务的一个方向交给独立 Agent 工作流处理，同时保留原任务的可审查上下文。它不是聊天消息的复制，也不能把完整历史、附件原文、密钥或工具授权无边界地带入子任务。

V1 中 Pi SDK、SQLite/FTS、语义搜索、轻量 LLM 摘要和自动 `delegate_task` 尚未在当前应用可用。V2 首轮基于主进程持久化的 `WorkSession`/`WorkEvent` 生成确定性上下文摘要；自动委派和搜索/导出在对应基础设施 Feature 后再引入。

## 首轮实现

- `WorkSession` 可带 `branch` 元数据：父任务、创建类型、受限上下文摘要、合并状态和时间戳。
- 从当前任务创建手动分支时继承项目、当前 Agent、模型覆盖、插件 id 和目标副本；不复制原附件数据或完整事件流。
- 主进程从目标、项目、当前 Agent 和最近有限工作事件生成摘要，持久化在分支内，用户可在右侧面板查看和编辑。
- 分支作为独立任务继续执行；侧栏按父子关系缩进显示，根任务和分支均可直接打开。
- 分支可合并回父任务：主进程在父任务时间线写入一条 `summary` 事件，包含分支标题、状态和末次可见结果；分支标为 `merged`。丢弃分支只归档子任务并标记 `discarded`，不影响父任务。

## 验收

- [x] 可从主任务创建、打开和继续独立的分支，重启后父子关系与摘要仍可恢复。
- [x] 分支只继承受限上下文和可安全复用的会话配置，不复制附件原文、完整历史或权限决定。
- [x] 摘要包含任务目标、项目、Agent 和最近工作活动，可查看、编辑并主进程持久化。
- [x] 分支侧栏以树形关系展示；合并、丢弃和归档分支均不破坏父任务。
- [x] 合并写入父任务可审查时间线事件，重复合并被拒绝。
- [ ] 自动 Agent 委派、LLM 摘要、SQLite/FTS、语义搜索、JSON/Markdown 导出和多层分支策略后续实现。

## 验证

桌面端创建带目标、项目和工作事件的任务分支，检查摘要不含附件 payload；重启应用后打开子分支并合并，确认父任务时间线只有一条合并结果事件。第二个分支丢弃后，父任务仍可恢复和继续。
