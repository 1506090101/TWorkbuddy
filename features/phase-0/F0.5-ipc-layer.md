# F0.5 — IPC 通信层与类型系统

> **Phase**: Phase 0 — 基础设施层 (Foundation)
> **Priority**: P0
> **Status**: 进行中 (已部分实现)
> **Dependencies**: F0.1 (项目初始化与工程骨架)

## 概述

F0.5 建立 Agent Buddy 主进程与渲染进程之间的安全通信桥接，通过 Electron 的 `contextBridge` API 为渲染进程提供类型安全的 API 调用接口。IPC 通信层是所有跨进程功能的基础设施，确保渲染进程在 `contextIsolation: true` 和 `nodeIntegration: false` 的安全约束下仍能高效地调用主进程能力。

本 Feature 的核心设计原则是"类型安全 + 通道分组 + 统一返回格式"。所有 IPC 通道按业务域分组管理（`agent:*`, `provider:*`, `settings:*`, `session:*`, `tool:*`, `git:*`, `mcp:*`, `workflow:*`, `workspace:*`），每个通道在主进程和 preload 脚本两端都使用精确的 TypeScript 类型定义，编译时即可发现类型不匹配。

统一返回类型 `IPCResult<T>` 封装了所有 IPC 调用的返回值结构：`{ success: boolean; data?: T; error?: string }`，渲染进程可以通过这个结构以统一模式处理成功和失败分支，无需针对每个通道写不同的错误处理逻辑。

## 验收标准

### 功能验收
- [ ] preload 脚本通过 `contextBridge.exposeInMainWorld` 暴露 `window.electronAPI` 对象
- [ ] 渲染进程通过 `window.electronAPI` 调用 IPC，无法直接访问 `ipcRenderer` 或 Node.js API
- [ ] 所有 IPC 通道按域分组，命名空间清晰：
  - `agent:*` — 6 个通道 (init/prompt/abort/steer/set-model/get-state)
  - `providers:*` — 6 个通道 (list/add/update/remove/test/detect-models)
  - `settings:*` — 2 个通道 (get/save)
  - `window:*` — 3 个通道 (minimize/maximize/close) + 事件监听
  - 预留: `session:*`, `tool:*`, `git:*`, `mcp:*`, `workflow:*`, `workspace:*`
- [ ] 所有 IPC 通道在主进程 (`ipcMain.handle`) 和 preload 端都有明确的 TypeScript 类型定义
- [ ] 统一返回类型 `IPCResult<T>` = `{ success: boolean; data?: T; error?: string }`
- [ ] 主进程错误被正确捕获并转换为 `IPCResult<T>` 格式返回（不 throw 到渲染进程）
- [ ] 事件监听（`onAgentEvent`）有正确的 unsubscribe 机制
- [ ] `contextIsolation: true` 和 `nodeIntegration: false` 安全策略生效

### 非功能验收
- [ ] IPC 调用延迟 < 5ms（本地进程间通信）
- [ ] 每个 IPC handler 的异常都被 try-catch 包裹
- [ ] TypeScript 编译时检查 IPC 通道名称和参数类型
- [ ] 不暴露 `ipcRenderer.invoke` 原始方法给渲染进程（只暴露封装后的方法）

// renderer/src/types/ipc.ts

// ============================================================
// 统一返回类型
// ============================================================
export interface IPCResult<T = void> {
  success: boolean
  data?: T
  error?: string
}

// ============================================================
// Provider 类型 (代理引用, 实际定义在 provider.ts)
// ============================================================
import type { ProviderConfig, AppSettings, ModelAssignment } from './provider'

// ============================================================
// ElectronAPI 接口 — 渲染进程侧类型定义
// ============================================================
export interface ElectronAPI {
  // ─── Agent 相关 ───
  initAgent: () => Promise<IPCResult<void>>
  prompt: (text: string, images?: ImageAttachment[]) => Promise<IPCResult<void>>
  abort: () => Promise<IPCResult<void>>
  steer: (text: string) => Promise<IPCResult<void>>
  setModel: (providerId: string, modelId: string) => Promise<IPCResult<void>>
  getState: () => Promise<AgentState | null>

  // 事件订阅
  onAgentEvent: (callback: (event: AgentEvent) => void) => () => void

  // ─── Provider 管理 ───
  listProviders: () => Promise<ProviderConfig[]>
  addProvider: (config: Omit<ProviderConfig, 'id'>) => Promise<ProviderConfig>
  updateProvider: (id: string, updates: Partial<ProviderConfig>) => Promise<IPCResult<void>>
  removeProvider: (id: string) => Promise<IPCResult<void>>
  testProvider: (id: string) => Promise<{ success: boolean; error?: string }>
  detectModels: (id: string) => Promise<string[]>

  // ─── 设置相关 ───
  getSettings: () => Promise<AppSettings>
  saveSettings: (settings: Partial<AppSettings>) => Promise<IPCResult<void>>

  // ─── 窗口控制 ───
  minimizeWindow: () => Promise<IPCResult<void>>
  maximizeWindow: () => Promise<IPCResult<void>>
  closeWindow: () => Promise<IPCResult<void>>
  onWindowStateChange: (callback: (state: WindowState) => void) => () => void

  // ─── 预留域 ─── (Phase 0 定义接口签名，后续实现)
  // session: SessionAPI
  // tools: ToolAPI
  // git: GitAPI
  // mcp: MCPAPI
  // workflow: WorkflowAPI
  // workspace: WorkspaceAPI
}

// ============================================================
// 辅助类型
// ============================================================
export interface ImageAttachment {
  data: string      // base64 编码 (不含前缀)
  mimeType: string  // "image/png" | "image/jpeg" | ...
}

export interface AgentState {
  isStreaming: boolean
  model: string
  thinkingLevel: 'off' | 'low' | 'medium' | 'high'
  messageCount: number
  currentModelRole: 'chat' | 'vision'
  chatModel: ModelRef | null
  visionModel: ModelRef | null
}

export interface WindowState {
  isMaximized: boolean
  isFocused: boolean
}

// Agent 事件类型 (来自 Pi SDK)

  | { type: 'agent_start' }
  | { type: 'turn_start' }
  | { type: 'message_update'; assistantMessageEvent: TextDeltaEvent }
  | { type: 'message_end'; message: { role: string; content: string } }
  | { type: 'tool_execution_start'; toolCallId: string; toolName: string; args: any }
  | { type: 'tool_execution_update'; toolCallId: string; output: string }
  | { type: 'tool_execution_end'; toolCallId: string; result: any; isError: boolean }
  | { type: 'agent_end' }
  | { type: 'agent_settled' }

export interface TextDeltaEvent {
  type: 'text_delta'
  delta: string
}

### IPC 通道

#### Agent 通道组 (`agent:*`)

| 通道 | 方向 | 参数 | 返回值 | 说明 |
|------|------|------|--------|------|
| `agent:init` | invoke→handle | 无 | `IPCResult<void>` | 初始化 Agent Session |
| `agent:prompt` | invoke→handle | `(text: string, images?: ImageAttachment[])` | `IPCResult<void>` | 发送用户消息（含图片） |
| `agent:abort` | invoke→handle | 无 | `IPCResult<void>` | 停止当前生成 |
| `agent:steer` | invoke→handle | `(text: string)` | `IPCResult<void>` | 流式期间引导消息 |
| `agent:set-model` | invoke→handle | `(providerId: string, modelId: string)` | `IPCResult<void>` | 手动切换模型 |
| `agent:get-state` | invoke→handle | 无 | `AgentState \| null` | 获取当前 Agent 状态 |
| `agent:event` | listen←main | `AgentEvent` | — | Agent 事件推送（主→渲染） |

#### Provider 通道组 (`providers:*`)

| 通道 | 方向 | 参数 | 返回值 | 说明 |
|------|------|------|--------|------|
| `providers:list` | invoke→handle | 无 | `ProviderConfig[]` | 获取所有 Provider |
| `providers:add` | invoke→handle | `(config: Omit<ProviderConfig, 'id'>)` | `ProviderConfig` | 添加 Provider |
| `providers:update` | invoke→handle | `(id: string, updates: Partial<ProviderConfig>)` | `IPCResult<void>` | 更新 Provider |
| `providers:remove` | invoke→handle | `(id: string)` | `IPCResult<void>` | 删除 Provider |
| `providers:test` | invoke→handle | `(id: string)` | `{success, error?}` | 测试 Provider 连接 |
| `providers:detect-models` | invoke→handle | `(id: string)` | `string[]` | 自动探测可用模型 |

#### Settings 通道组 (`settings:*`)

| 通道 | 方向 | 参数 | 返回值 | 说明 |
|------|------|------|--------|------|
| `settings:get` | invoke→handle | 无 | `AppSettings` | 获取完整设置 |
| `settings:save` | invoke→handle | `(settings: Partial<AppSettings>)` | `IPCResult<void>` | 保存设置 |

#### Window 通道组 (`window:*`)

| 通道 | 方向 | 参数 | 返回值 | 说明 |
|------|------|------|--------|------|
| `window:minimize` | invoke→handle | 无 | `IPCResult<void>` | 窗口最小化 |
| `window:maximize` | invoke→handle | 无 | `IPCResult<void>` | 窗口最大化/还原 |
| `window:close` | invoke→handle | 无 | `IPCResult<void>` | 关闭窗口 |
| `window:state-change` | listen←main | `WindowState` | — | 窗口状态变化 |

#### 预留通道组 (Phase 0 仅定义，后续实现)

| 域名 | 预留通道 | 说明 |
|------|---------|------|
| `session:*` | `list`, `create`, `delete`, `switch`, `export` | 会话管理 (F1.4) |
| `tool:*` | `list`, `execute`, `confirm`, `deny` | 工具执行与权限 (F1.6) |
| `git:*` | `status`, `diff`, `log`, `commit`, `branch`, `checkout`, `stash` | Git 操作 (F1.10) |
| `mcp:*` | `list-servers`, `add`, `remove`, `start`, `stop`, `list-tools` | MCP 管理 (F3.1) |
| `workflow:*` | `list`, `create`, `update`, `delete`, `toggle`, `get-history` | 工作流 (F6.1) |
| `workspace:*` | `list`, `open`, `close`, `get-context` | 多项目 (F3.3) |

### 关键实现逻辑

#### 1. 主进程 IPC 处理器入口

```typescript
// main/ipc.ts
import { ipcMain, BrowserWindow } from 'electron'
import { initAgent, prompt, abort, steer, setModel, getState } from './agent'
import {
  getSettings, saveSettings,
  addProvider, updateProvider, removeProvider
} from './settings'
import { providerManager } from './provider-manager'
import type { ProviderConfig, AppSettings } from '../renderer/src/types/provider'
import type { IPCResult, ImageAttachment } from '../renderer/src/types/ipc'

/**
 * 注册所有 IPC 处理器
 */
export function registerIpcHandlers(win: BrowserWindow): void {
  // =============================================
  // Agent 通道组
  // =============================================
  ipcMain.handle('agent:init', async (): Promise<IPCResult<void>> => {
    try {
      await initAgent(win)
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('agent:prompt', async (
    _event,
    text: string,
    images?: ImageAttachment[]
  ): Promise<IPCResult<void>> => {
    try {
      await prompt(text, images)
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('agent:abort', async (): Promise<IPCResult<void>> => {
    try {
      await abort()
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('agent:steer', async (_event, text: string): Promise<IPCResult<void>> => {
    try {
      await steer(text)
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('agent:set-model', async (
    _event, providerId: string, modelId: string
  ): Promise<IPCResult<void>> => {
    try {
      await setModel(providerId, modelId)
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('agent:get-state', async () => {
    return getState()
  })

  // =============================================
  // Provider 通道组
  // =============================================
  ipcMain.handle('providers:list', async () => {
    return providerManager.getProviders()
  })

  ipcMain.handle('providers:add', async (
    _event, config: Omit<ProviderConfig, 'id'>
  ) => {
    return addProvider(config)
  })

  ipcMain.handle('providers:update', async (
    _event, id: string, updates: Partial<ProviderConfig>
  ): Promise<IPCResult<void>> => {
    try {
      updateProvider(id, updates)
      providerManager.reload()
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('providers:remove', async (
    _event, id: string
  ): Promise<IPCResult<void>> => {
    try {
      removeProvider(id)
      providerManager.reload()
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('providers:test', async (_event, id: string) => {
    return await providerManager.testConnection(id)
  })

  ipcMain.handle('providers:detect-models', async (_event, id: string) => {
    return await providerManager.detectModels(id)
  })

  // =============================================
  // Settings 通道组
  // =============================================
  ipcMain.handle('settings:get', async () => {
    return getSettings()
  })

  ipcMain.handle('settings:save', async (
    _event, settings: Partial<AppSettings>
  ): Promise<IPCResult<void>> => {
    try {
      saveSettings(settings)
      providerManager.reload()
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  // =============================================
  // Window 通道组
  // =============================================
  ipcMain.handle('window:minimize', async (): Promise<IPCResult<void>> => {
    try {
      win.minimize()
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('window:maximize', async (): Promise<IPCResult<void>> => {
    try {
      if (win.isMaximized()) {
        win.unmaximize()
      } else {
        win.maximize()
      }
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  ipcMain.handle('window:close', async (): Promise<IPCResult<void>> => {
    try {
      win.close()
      return { success: true }
    } catch (err: any) {
      return { success: false, error: err.message }
    }
  })

  // 窗口状态事件监听（主→渲染推送）
  win.on('maximize', () => {
    win.webContents.send('window:state-change', { isMaximized: true, isFocused: win.isFocused() })
  })
  win.on('unmaximize', () => {
    win.webContents.send('window:state-change', { isMaximized: false, isFocused: win.isFocused() })
  })
  win.on('focus', () => {
    win.webContents.send('window:state-change', { isMaximized: win.isMaximized(), isFocused: true })
  })
  win.on('blur', () => {
    win.webContents.send('window:state-change', { isMaximized: win.isMaximized(), isFocused: false })
  })
}
```

#### 2. Preload 脚本 (contextBridge)

```typescript
// preload/index.ts
import { contextBridge, ipcRenderer } from 'electron'
import type { ElectronAPI, ImageAttachment, AgentEvent, WindowState } from '../renderer/src/types/ipc'
import type { ProviderConfig, AppSettings } from '../renderer/src/types/provider'

const electronAPI: ElectronAPI = {
  // ─── Agent ───
  initAgent: () => ipcRenderer.invoke('agent:init'),
  prompt: (text, images) => ipcRenderer.invoke('agent:prompt', text, images),
  abort: () => ipcRenderer.invoke('agent:abort'),
  steer: (text) => ipcRenderer.invoke('agent:steer', text),
  setModel: (providerId, modelId) => ipcRenderer.invoke('agent:set-model', providerId, modelId),
  getState: () => ipcRenderer.invoke('agent:get-state'),

  onAgentEvent: (callback) => {
    const handler = (_event: Electron.IpcRendererEvent, data: AgentEvent) => callback(data)
    ipcRenderer.on('agent:event', handler)
    return () => {
      ipcRenderer.removeListener('agent:event', handler)
    }
  },

  // ─── Providers ───
  listProviders: () => ipcRenderer.invoke('providers:list'),
  addProvider: (config) => ipcRenderer.invoke('providers:add', config),
  updateProvider: (id, updates) => ipcRenderer.invoke('providers:update', id, updates),
  removeProvider: (id) => ipcRenderer.invoke('providers:remove', id),
  testProvider: (id) => ipcRenderer.invoke('providers:test', id),
  detectModels: (id) => ipcRenderer.invoke('providers:detect-models', id),

  // ─── Settings ───
  getSettings: () => ipcRenderer.invoke('settings:get'),
  saveSettings: (settings) => ipcRenderer.invoke('settings:save', settings),

  // ─── Window ───
  minimizeWindow: () => ipcRenderer.invoke('window:minimize'),
  maximizeWindow: () => ipcRenderer.invoke('window:maximize'),
  closeWindow: () => ipcRenderer.invoke('window:close'),
  onWindowStateChange: (callback) => {
    const handler = (_event: Electron.IpcRendererEvent, state: WindowState) => callback(state)
    ipcRenderer.on('window:state-change', handler)
    return () => {
      ipcRenderer.removeListener('window:state-change', handler)
    }
  },
}

contextBridge.exposeInMainWorld('electronAPI', electronAPI)
```

## UI/UX 规范

本 Feature 无直接 UI 界面。但以下约束影响 UI 开发：

- 渲染进程代码中调用 `window.electronAPI.*` 获取数据，不能直接访问 `require('electron')` 或 `ipcRenderer`
- IPC 调用失败时，渲染进程应检查 `IPCResult.success` 字段并显示对应错误提示
- 事件监听（`onAgentEvent`, `onWindowStateChange`）必须在组件 `useEffect` cleanup 中 unsubscribe

## 测试要点

- **单元测试**:
  - `IPCResult<T>` 类型的正确性验证（success/error 互斥）
  - preload 脚本暴露的方法签名与 `ElectronAPI` 接口一致
- **集成测试**:
  - 每个 IPC 通道的单向调用测试：invoke → handle → response
  - 异常处理：主进程 throw → 渲染进程收到 `{ success: false, error }`
  - 事件订阅/取消订阅：`onAgentEvent` 注册后收到事件，unsubscribe 后不再收到
- **E2E 测试**:
  - 验证 `window.electronAPI` 在渲染进程中可访问
  - 验证 `require('electron')` 在渲染进程中不可用（抛出 ReferenceError）
  - 验证 `window.ipcRenderer` 在渲染进程中不可用
- **安全检查**:
  - `contextIsolation: true` 已启用
  - `nodeIntegration: false` 已启用
  - 渲染进程无文件系统访问权限

## 开放问题

1. **sandbox 策略**: 当前 `sandbox: false` 是 MVP 临时方案。开启 sandbox 后 preload 脚本中 `ipcRenderer` 是否仍然可用？需要验证。
2. **IPC 性能**: 大量 Agent 文本增量事件通过 IPC 推送是否有延迟？是否需要合并（throttle/batch）？
3. **错误统一处理**: 是否在主进程侧统一 wrap 所有 handler 以自动捕获异常？
4. **IPC 通道数量**: 随着 Feature 增加，IPC 通道会超过 50 个。是否需要引入通道注册机制自动验证完整性？

## 备注

- IPC 通道命名规范：`{domain}:{action}`，全小写，用短横线分隔
- 预留通道组在本 Feature 中仅作为注释和类型定义存在，不注册 `ipcMain.handle`
- 事件推送 (`webContents.send`) 使用独立通道名（如 `agent:event`, `window:state-change`），与 invoke/handle 通道分开
- 所有 API Key 传输仅限于主进程内的 Provider 管理器，永远不通过 IPC 发送到渲染进程
