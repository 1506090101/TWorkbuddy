# F0.6 — 状态管理基础设施

> **Phase**: Phase 0 — 基础设施层 (Foundation)
> **Priority**: P0
> **Status**: 进行中 (已部分实现)
> **Dependencies**: F0.1 (项目初始化与工程骨架), F0.5 (IPC 通信层与类型系统)

## 概述

F0.6 建立 Agent Buddy 的前端状态管理基础设施，以 Zustand 为核心构建分层 store 架构，统一管理应用的全局状态、UI 状态、业务数据和持久化策略。状态管理是所有 UI 组件的数据源和交互枢纽，直接影响应用的响应速度、数据一致性和开发体验。

Store 按业务领域拆分为 8 个独立 store，遵循"单一职责、按需组合"原则。每个 store 使用 Zustand 的 `create()` API 定义状态和 actions，通过 immer middleware 实现不可变更新，通过 devtools middleware 提供 Redux DevTools 调试支持。状态选择器使用 `useShrinkSelector` 模式避免不必要的组件重渲染。

持久化策略分层：`uiStore` 管理纯本地状态（布局折叠、当前视图、主题模式）默认不持久化或通过 `electron-store` 选择性持久化；业务 stores（`settingsStore`, `providerStore`）通过 IPC 与主进程的 `electron-store` 同步；会话和聊天 stores（`sessionStore`, `chatStore`）暂存于内存中，后续 Phase 1 接入 SQLite 持久化。

### 关键实现逻辑

#### 1. 共享 Middleware 配置

```typescript
// renderer/src/stores/middleware.ts
import { StateCreator } from 'zustand'
import { devtools } from 'zustand/middleware'
import { immer } from 'zustand/middleware/immer'

/**
 * 为 store 包装标准 middleware 组合
 * - immer: 不可变更新（可选，简单 store 可不用）
 * - devtools: Redux DevTools 调试 (仅开发模式)
 */
export function withStandardMiddleware<T>(
  storeName: string,
  creator: StateCreator<T, [['zustand/immer', never]], [], T>
): StateCreator<T, [], [['zustand/devtools', never], ['zustand/immer', never]]> {
  const withImmer = immer(creator)

  if (import.meta.env.DEV) {
    return devtools(withImmer, { name: storeName })
  }

  // Production: 仍使用 immer，但不包装 devtools
  // (devtools middleware 在 production 有轻微性能开销)
  return withImmer as any
}
```

#### 2. UI Store 实现

```typescript
// renderer/src/stores/uiStore.ts
import { create } from 'zustand'
import type { UIState, ThemeMode } from './types'
import { LAYOUT_CONSTANTS } from '../types/layout'

const THEME_STORAGE_KEY = 'agent-buddy-theme'

export const useUILayoutStore = create<UIState>()((set, get) => ({
  // ─── Layout State ───
  sidebarExpanded: true,
  sidebarWidth: LAYOUT_CONSTANTS.SIDEBAR_EXPANDED_WIDTH,
  sidebarTransitioning: false,
  rightPanelExpanded: false,
  rightPanelWidth: LAYOUT_CONSTANTS.RIGHT_PANEL_DEFAULT_WIDTH,
  rightPanelMode: null,

  // ─── Theme State ───
  theme: (localStorage.getItem(THEME_STORAGE_KEY) as ThemeMode) || 'system',
  resolvedTheme: 'light',

  // ─── Window State ───
  isMaximized: false,
  isFocused: true,

  // ─── Layout Actions ───
  toggleSidebar: () => {
    const { sidebarExpanded, expandSidebar, collapseSidebar } = get()
    if (sidebarExpanded) collapseSidebar()
    else expandSidebar()
  },

  expandSidebar: () => set({ sidebarExpanded: true }),
  collapseSidebar: () => set({ sidebarExpanded: false }),
  setSidebarTransitioning: (value) => set({ sidebarTransitioning: value }),

  openRightPanel: (mode) => set({
    rightPanelExpanded: true,
    rightPanelMode: mode
  }),

  closeRightPanel: () => set({
    rightPanelExpanded: false,
    rightPanelMode: null
  }),

  setRightPanelWidth: (width) => set({
    rightPanelWidth: Math.max(
      LAYOUT_CONSTANTS.RIGHT_PANEL_MIN_WIDTH,
      Math.min(width, LAYOUT_CONSTANTS.RIGHT_PANEL_MAX_WIDTH)
    )
  }),

  // ─── Theme Actions ───
  setTheme: (theme) => {
    localStorage.setItem(THEME_STORAGE_KEY, theme)
    set({ theme })
    get().resolveTheme()
  },

  resolveTheme: () => {
    const { theme } = get()
    let resolved: 'light' | 'dark'

    if (theme === 'system') {
      resolved = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
    } else {
      resolved = theme
    }

    // 应用到 DOM
    const root = document.documentElement
    root.classList.remove('light', 'dark')
    if (resolved === 'dark') {
      root.classList.add('dark')
    }

    set({ resolvedTheme: resolved })
  },

  toggleTheme: () => {
    const { resolvedTheme, setTheme } = get()
    setTheme(resolvedTheme === 'dark' ? 'light' : 'dark')
  },

  // ─── Window Actions ───
  setWindowState: (state) => set({
    isMaximized: state.isMaximized,
    isFocused: state.isFocused
  }),
}))
```

#### 3. Chat Store 实现

```typescript
// renderer/src/stores/chatStore.ts
import { create } from 'zustand'
import { immer } from 'zustand/middleware/immer'
import { devtools } from 'zustand/middleware'
import type { ChatState, ChatMessage, ToolCallInfo } from './types'

export const useChatStore = create<ChatState>()(
  devtools(
    immer((set) => ({
      messages: [],
      isAgentRunning: false,
      currentSessionId: null,

      addUserMessage: (text, images) =>
        set((state) => {
          state.messages.push({
            id: crypto.randomUUID(),
            role: 'user',
            content: text,
            images: images?.map((img, i) => ({
              id: `img-${Date.now()}-${i}`,
              data: img.data,
              mimeType: img.mimeType,
              name: `image-${i + 1}`,
            })),
            timestamp: Date.now(),
          })
        }),

      startAssistantMessage: (agentId, agentName) =>
        set((state) => {
          state.messages.push({
            id: crypto.randomUUID(),
            role: 'assistant',
            content: '',
            isStreaming: true,
            timestamp: Date.now(),
            agentId,
            agentName,
          })
        }),

      appendTextDelta: (delta) =>
        set((state) => {
          const last = state.messages[state.messages.length - 1]
          if (last && last.role === 'assistant' && last.isStreaming) {
            last.content += delta
          }
        }),

      finishAssistantMessage: () =>
        set((state) => {
          const last = state.messages[state.messages.length - 1]
          if (last && last.role === 'assistant') {
            last.isStreaming = false
          }
        }),

      addToolCall: (toolCall) =>
        set((state) => {
          const last = state.messages[state.messages.length - 1]
          if (last && last.role === 'assistant') {
            if (!last.toolCalls) last.toolCalls = []
            last.toolCalls.push(toolCall)
          }
        }),

      updateToolCall: (id, updates) =>
        set((state) => {
          const last = state.messages[state.messages.length - 1]
          if (last && last.toolCalls) {
            const tc = last.toolCalls.find((t) => t.id === id)
            if (tc) Object.assign(tc, updates)
          }
        }),

      setAgentRunning: (running) =>
        set((state) => { state.isAgentRunning = running }),

      clearMessages: () =>
        set((state) => { state.messages.length = 0 }),

      setCurrentSession: (sessionId) =>
        set((state) => { state.currentSessionId = sessionId }),
    })),
    { name: 'chatStore' }
  )
)
```

function MultiFieldComponent() {
  const { isAgentRunning, messages } = useChatStore(
    useShallow((s) => ({
      isAgentRunning: s.isAgentRunning,
      messages: s.messages,
    }))

    <div>
      {isAgentRunning ? 'Running' : 'Idle'} ({messages.length} messages)

## UI/UX 规范

本 Feature 无直接 UI 界面，但以下 store 设计影响 UI 行为：

- **主题切换** (`uiStore.theme`): 切换 `light/dark/system` 时通过 `resolveTheme()` 立即更新 `document.documentElement` 的 class 和 `resolvedTheme` 字段
- **面板状态** (`uiStore.sidebarExpanded`, `uiStore.rightPanelExpanded`): 所有面板组件读取这些字段控制折叠/展开
- **流式状态** (`chatStore.isAgentRunning`): 用于 UI 上显示/隐藏"停止生成"按钮和加载指示器
- **Toast 生命周期**: `toastStore.addToast()` → 渲染 → 定时器 → `removeToast()`，由 Toast 组件消费

## 测试要点

- **单元测试**:
  - 每个 store 的 actions 正确修改 state（使用 `act()` 包裹）
  - Immer middleware: 验证直接 mutate state 不报错，且不在原对象上修改
  - 选择器优化: 验证组件只在订阅的字段变化时才重渲染（可用 React Testing Library 的 `rerender` 计数）
- **集成测试**:
  - UI Store 主题切换：`setTheme('dark')` → `resolvedTheme === 'dark'` → DOM 上有 `dark` class
  - Chat Store 流式追加：逐 token 追加后 content 累积正确
  - Provider Store + IPC: `addProvider()` 调用 IPC，返回新 Provider 后 store 更新
- **E2E 测试**:
  - 验证 devtools 在生产构建中不可用（`__ZUSTAND_DEVTOOLS__` 不暴露）
- **持久化测试**:
  - 验证主题设置（`localStorage`）页面刷新后保持
  - 验证 Provider 设置（`electron-store`）应用重启后读取正确

## 开放问题

1. **Session 持久化时机**: 当前 `sessionStore` 和 `chatStore` 是内存 store，何时引入 SQLite 持久化（Phase 1 F1.4）？
2. **Store 拆分粒度**: 是否将 `uiStore` 进一步拆分为 `layoutStore` + `themeStore` + `windowStore`？还是保持一个 store 方便协同访问？
3. **Zustand v5**: 是否需要跟随 Zustand v5 的新 API（`useStore` with `selector` prop pattern）？
4. **持久化 middleware**: 是否需要引入 `zustand/middleware/persist` 自动同步到 `localStorage`/`electron-store`？还是保持手动同步？
5. **Cross-store 通信**: 当一个 store 的 action 需要触发另一个 store 的 action 时（如发送消息后清空图片队列），使用何种模式？`get().otherStore.method()` 还是事件总线？

## 备注

- Store 文件按业务域拆分而非技术类型，便于每个 Feature 团队独立开发
- `chatStore` 使用 immer middleware 是因为流式追加操作频繁，mutable 模式比 spread 操作性能更好
- `settingsStore` 和 `providerStore` 的 `load*` actions 在 App.tsx 初始化时调用一次
- `useShallow` 是 Zustand 4.5+ 的官方选择器优化 hook，替代社区 `useShrinkSelector`
- 所有 store 不应在初始化时进行异步操作（避免 Suspense 边界），异步加载通过 `load*` actions 手动触发
